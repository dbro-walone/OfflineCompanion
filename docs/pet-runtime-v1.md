# Pet Runtime v1

Rust 版的角色行为只有一条数据通路：业务层产生 `BusinessFact`，`AppRuntime` 将其归一为 `PetEvent`，`BehaviorController` 根据状态、心情、会话和优先级选择语义动作，`PackageCatalog` 将语义动作解析成动画定义，`AnimationPlayer` 最终产生 `RenderState`。Slint 只负责显示和输入，不保存业务状态，也不直接选择帧。

动作目录返回完整 `RuntimeAction`：动作 ID、语义、触发器、权重、冷却、优先级、动画文件和动作自己的 `RenderSource`。空闲调度首次至少等待 10 秒，之后间隔 20～60 秒；先过滤禁用包、冷却和最近三个动作，再按权重选择。测试使用固定随机源，生产使用本地确定性随机序列，不访问网络。

## 优先级与打断

优先级从高到低为系统安全、用户直接输入、提醒注意、业务反馈、专注陪伴、主动邀请和随机空闲。`Scheduler` 在播放器整个生命周期保存 `ActiveAction`，低优先级请求不能覆盖正在处理的高优先级请求。不可打断动画只在安全帧边界切换；动画完成只发出一次内部完成事件。`resumePolicy=previous/resume` 恢复原播放器和图集，`idle` 或普通一次性动作回到角色默认动作。

## 互动与运动

- 鼠标进入配置距离后触发一次好奇反馈，等待回应最多 4 秒；点击、离开或超时结束会话，默认冷却 30 秒。
- 点击按角色窗口高度区分头部和身体；拖动开始后不会再产生点击。
- `LocomotionController` 在运行时入口前将释放分类成 Drop、EdgeLeft、EdgeRight 或 Thrown；飞行速度和位移均有上限，物理结束发送 Landing，随后进入落地或受惊恢复动作。
- 宠物、前台窗口和光标显示器使用独立 API；拖放按宠物显示器夹取，提醒按前台窗口显示器定位，并周期处理显示器热插拔后的越界恢复。
- “减少动态效果”开启时，主动邀请、提醒和拖放只做原地低动态反馈，不跨屏移动。

## 安全边界

运行时完全离线，不读取屏幕内容、键盘内容或剪贴板，不模拟点击，不加载脚本、动态库或可执行文件。无效资源包只会被拒绝或从能力目录中移除；缺失动作会回退到当前角色的默认动作，不能导致应用崩溃。

## 诊断

`BehaviorController::traces` 保存最近 128 条 `DecisionTrace`，包括事件、状态、心情、选择动作、原因和回退信息。该信息只存在本机内存中，不上传。
